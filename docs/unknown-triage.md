# Этап 1: разбор UNKNOWN до изменения правил

Исходная точка — правила v2, 60 тестовых проектов, 2360 UNKNOWN.
Скрипт `benchmarks/triage.py` читает сохранённые решения, сверяет числа с таблицей
и группирует исходные свидетельства. Никакие решения не изменяются.
Полная детализация: [unknown-triage-v2.json](unknown-triage-v2.json).

Выявлены четыре разных задачи:

1. Большинство source-only — lockfiles Rust/JavaScript. Они могут описывать
   другие платформы и зависимости сборки; автоматически включать их нельзя.
2. Значительная часть неоднозначных записей — GitHub Actions в CI. Это отдельный
   класс конфигурации сборки, а не доказанная ошибка идентификации runtime-пакета.
   Нужна отдельная причина в review, с сохранением исходных наблюдений.
3. Go stdlib записана Syft как `version=go1.24.13`, но её PURL содержит `1.24.13`.
   Это проверяемая разница представления, а не повод подменять любую версию.
   Нужна узкая нормализация только stdlib с сохранением исходных полей в экспорте.
4. 260 наблюдений binary-classifier не имеют достаточно сильной metadata.
   Один fingerprint не доказывает идентичность и должен остаться UNKNOWN.

Дополнительная проверка нужна уже для INCLUDE: metadata может остаться без
payload-файлов. В следующем этапе тесты заранее зададут присутствующие,
удалённые, декларативные и metadata-only пакеты для всех шести языков.
Порог успеха задаётся ожидаемым составом, а не числом удалённых записей.
