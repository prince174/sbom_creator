2026-10-13, исходный commit 7d25a74. Чистое дерево; benchmark-процессов нет.
**Не внедрён. Runtime 0.6.0, frozen P1 и guard не менялись.**

Гипотеза: ограничить root pyproject до 1 МиБ и входной граф данных до 250000
узлов, 16 Ми символов строк (включая ключи), глубины64. Значения выбраны
экспериментально, не из требований Syft или PyPA.

Loader читает только регулярный файл, проверяет идентичность inode/device
до/после открытия, использует O_NOFOLLOW/O_NONBLOCK где доступны, отклоняет
Windows reparse attribute. Ограничивает чтение до LIMIT+1; invalid TOML/UTF8,
дубликаты ключей, превышения и ошибки чтения дают UNKNOWN без эха содержимого.
Это не доказательство безопасности при конкурентной записи в checkout, и не
ограничение памяти JSON parser до загрузки image в объекты Python.

36 unit tests passed, 1 skipped: Windows не разрешила создание symlink.
Ruff passed. Однако реальный replay **не прошёл критерий принятия**:
полные Syft image каталоги имеют 305602–317102 узла, около3.2М символов,
глубину8. Все четыре входа отклонены по числу узлов. Размер manifest не виноват:
loader сохранил все четыре документа и их SHA.
