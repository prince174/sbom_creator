# Версия 0.3.0: проверка файлов пакетов без LLM

30 сентября 2026. Все испытания выполнены на контролируемых тестовых сборках.
API и CLI по умолчанию используют `image-evidence-and-payload-v3`. Отдельная
модель для этого режима не нужна.

## Что изменилось

1. Разобраны причины 2360 UNKNOWN в исходном прогоне: [разбор](unknown-triage.md).
   CI references отделены от runtime-зависимостей причиной `CI_CONFIGURATION`.
2. Собраны независимые контрольные приложения на всех шести языках: две версии
   пакета, source-only/dev декларации, пакет, удалённый отдельным слоем,
   metadata без payload. [Методика](native-golden.md).
3. Добавлена проверка файлов конечного образа. Python использует RECORD, npm —
   код, объявленный main или стандартный index (включая JSON), Ruby — gem-файлы и стандартные
   расширения в каталоге платформы, Java — class внутри JAR, Go/Rust — binary.
   Это пассивное ограниченное чтение архива, без запуска или извлечения файлов.
4. Проверены повторное сканирование тестовых образов, установленный Linux-сервис,
   сквозной HTTP-запрос, экспорт и валидация CycloneDX. Прежние попытки сохранены.

Windows пропускает symlink-тест из-за прав ОС; он проходит в Linux. Две ранние
попытки Linux suite не имели полного mount вспомогательных test fixtures; их
диагностика сохранена локально в `benchmarks/.work/verification-history-v3`.
Итоговый запуск включает все fixtures и не импортирует host src.

Сквозной HTTP-тест использовал точный commit существующего Bitbucket Python fixture
и его тестовый образ. Проверены 401 без авторизации, 202 при приёме, succeeded,
скачивание всех 9 артефактов, schema и сохранение `pkg:pypi/demo-app@1.0.0`.
Образ пришёл из отдельного локального HTTPS registry; соответствие config digest
тестовой сборке проверено. Временные контейнеры удалены, host CA не менялся.

Один запрос занял **17,297 с**, максимальный наблюдавшийся расход памяти сервиса —
**344,1 MiB**, CPU — **156,07%** (100% соответствует одному CPU). Лимит контейнера:
2 CPU / 1 GiB; Docker daemon и registry в расход сервиса не входят. Сэмплы снимались
периодически на общем хосте; это не изолированный нагрузочный тест и не гарантия SLA.
Результат: 113 компонентов CycloneDX и 1 UNKNOWN. Windows и Linux каталоги того же
образа могут различаться по обнаружению binary classifiers; полное равенство
между платформами этими испытаниями не заявляется.

## Границы результата

Подтверждён хотя бы один относящийся к пакету файл, а не целостность всех файлов,
исполнение кода или применимость CVE. Пакеты ОС по-прежнему оцениваются по пакетной
metadata. Resource-only JAR, Python без RECORD, встроенные Ruby-компоненты без
отдельного файла и другие неподдержанные layouts могут остаться UNKNOWN.
В частности, `ruby2_keywords` из тестового Ruby runtime не имеет подтверждённого
отдельного payload и остаётся в review; это не доказательство его отсутствия.

`build_link=unverified` остаётся честной границей: произвольная пара commit/image
не доказывает происхождение production-сборки. Реальных production-сборок пока нет.
Загрузка в Dependency-Track остаётся ручной.

Всего 10255 записей компонентов и 2360 UNKNOWN-идентичностей. Все 60 результатов имеют partial coverage; точная release-идентичность основного пакета включена в 54 из 59 применимых случаев. Это 57 публичных GitHub проектов и 3 Bitbucket Python fixtures.

Это новые source/image сканы тех же immutable тестовых образов с проверкой payload, а не replay старого решения. Сборки повторно не выполнялись. После уточнения npm/Ruby повторены затронутые сканы; предыдущие outputs сохранены.

Время — последний вызов анализа, без сборки; общий хост, не изолированный benchmark. Source/Image/Final считают записи пакетов, INCLUDE/UNKNOWN — идентичности. Полный ожидаемый состав 60 образов не размечен, поэтому FP/FN этой выборки не вычисляются.

Общее число записей совпало с v2, но состав изменился: в десяти Go-образах добавлен подтверждённый stdlib; в десяти Ruby-образах `ruby2_keywords` перенесён в UNKNOWN. Это не десять доказанных FP. Для npm оба SPDX data-пакета сохранены.
