# Версия 0.2.0: рабочий режим без LLM

30 сентября 2026. API, CLI `analyze` / `analyze-local` и библиотечный pipeline
по умолчанию работают по правилам `image-evidence-only-v2`. Модель, её URL и ключ
не нужны. HTTP API не принимает переключатель модели. Экспериментальный CLI
`--mode llm` сохранён отдельно и не вызывается автоматически.

## Что исправлено

- Положительное решение по идентичности включает только записи с подтверждающей
  metadata образа. Декларация из lockfile с тем же PURL не получает статус
  установленного пакета за счёт соседней записи. Все наблюдения остаются в raw
  Syft и decisions; `selected_image_artifact_ids` объясняет точный состав экспорта.
- Более 100 копий одного пакета не ломают контракт оценщика: ссылки в assessment
  ограничены, полные свидетельства и все подтверждённые расположения сохраняются.
- `review.json` содержит UNKNOWN, причины, версии и следующие шаги проверки.
  Причины агрегируются в summary и coverage. CycloneDX содержит режим, версию
  политики и статус покрытия, чтобы неполнота оставалась видимой после экспорта.
- Benchmark cache старой политики не выдаётся за результат текущей. Старые
  артефакты сохранены; повторный анализ создаёт отдельный результат.

## Что означает результат контрольного образа

`benchmarks/golden.py` до сканирования записывает ожидаемые идентичности, создаёт
небольшие Python/npm payloads с metadata, собирает `FROM scratch` через COPY,
затем пропускает source и образ через настоящий Syft и CLI pipeline без модели.
Образ не запускается. Сценарии: source-only, copied locks, разные версии,
две доставленные версии, image-only и несколько установленных расположений.

Все пять ожидаемых идентичностей сохранены; ни одна из пяти отрицательных не
включена. Syft наблюдал 9 из 10 контрольных идентичностей: npm dev-зависимость
из lockfile не попала в каталог. Это явно записано в отчёте. Такой тест не
доказывает полноту сканирования dev-зависимостей, реальную работу установщиков,
фактическое выполнение кода или отсутствие FP/FN на production-проектах.

Повторение с новыми путями, чтобы сохранить прежние свидетельства:

```powershell
.\.venv\Scripts\python.exe benchmarks\golden.py `
  --work benchmarks/.work/golden-new `
  --report docs/verification-golden-new.json `
  --syft G:/code/sbom_creator/.tools/syft/syft.exe
```

## Оставшиеся границы

Сервис строит подтверждённую по metadata инвентаризацию. Пакетная metadata может
быть устаревшей или скопированной; наличие не равно использованию кода. В частности,
`package.json`, найденный JavaScript package cataloger, идентифицирует пакет,
но сам по себе не доказывает наличие всех его payload-файлов. Скрытые зависимости,
shading, vendoring и stripped binaries требуют дополнительных методов анализа.
UNKNOWN не считается доказанно лишней зависимостью и не получает выдуманную версию.
Связь commit с production image остаётся `unverified` без внешнего подтверждения сборки.
