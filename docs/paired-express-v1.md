# R3: парный образ Express и сборочный CycloneDX

Получена проверенная пара для Express 4.21.2, commit
`1faf228935aa0a13111f92c28ee795be64ce3f0f`, linux/amd64.
Это подготовка оценки, не улучшение алгоритма сервиса.

| Проверка | Результат |
|---|---:|
| Прямые зависимости package.json / корневые рёбра CycloneDX | 31 / 31 |
| Версии эталона совпадают с lockfile и установленными package.json | 31 / 31 |
| Записи дерева приложения, проверенные между builder и runtime | 1048 |
| Координаты эталонных прямых зависимостей в final B0 | 31 / 31 |
| Компоненты final / OS / full | 267 / 89 / 356 |
| Записи dependencies в final B0 | 0 |
| UNKNOWN-решения B0 | 13: 4 image evidence, 9 CI configuration |
| Precision / recall / F1 прямых рёбер | Не определены: B0 их не предсказывает |

31/31 — покрытие координат в инвентаризации, не 100% точности прямых зависимостей.
Остальные записи final не объявляются FP: B0 выводит инвентаризацию, а не множество
прямых зависимостей проекта. Анализ успешно завершён с `partial=true`.

Сборка использует закреплённый digest node:22-bookworm-slim и CycloneDX npm 6.0.1.
`.npmrc` Express отключает lockfile; в тестовом профиле явно указан
`--package-lock=true`. Установка production-зависимостей выполняется с отключёнными
скриптами, затем npm pack. Express не требует отдельной компиляции.
Исходный checkout не изменён. Полученный lockfile сохранён как артефакт сборки,
не добавлен в checkout анализатора. Свежий запуск может разрешить другие версии:
он создаёт новую пару, а не обещает побайтовое воспроизведение старого образа.

CycloneDX запускается в builder. В runtime копируется только `/src` → `/app`;
генератор и `/reference/sbom.json` туда не попадают. До анализа сравниваются пути,
типы, режимы доступа, содержимое файлов и цели ссылок приложения. Время, владельцы
и xattrs в это сравнение не входят. В инвентаризации runtime генератор отсутствует.
Анализатор получает только чистый checkout и образ через явный archive-режим
внешнего benchmark. В production runtime Docker не добавлялся.

Первый прогон остановился из-за отсутствующего lockfile; затем проверка harness
ошибочно сравнила OCI index с config digest. Исправлена привязка по проверенной
цепочке OCI index → linux/amd64 manifest → config. Syft при чтении docker-archive
может синтезировать Docker manifest с другим digest; совпадение подтверждается
проверенными байтами config, включающими rootfs diff IDs. Обе формы manifest digest
сохранены отдельно. Проверка возобновлена на готовых артефактах без новой сборки.

Пять unit-тестов проверяют изменение содержимого/режима файла, разделение index/config,
повреждённые blob, неоднозначную платформу и детерминированность разделения выборки.
Все три выходных SBOM повторно проверены по схеме. Полное время сборки/анализа и
пиковые CPU/RSS не восстановлены после возобновления; значения `null`, а не оценки.
В summary сохранены 6.157 секунды reconciliation, это не время полного pipeline.

Повтор проверки: `python benchmarks/verify_paired_express.py` (нужны локальные
архивы в `.work/paired-express-v1`). Для отдельного нового прогона:
`python benchmarks/paired_express.py --run-id <новое-имя>`. Завершённый receipt
не перезаписывается. `--resume-validation` предназначен только для незавершённого
прогона с готовыми артефактами и неизменным рецептом.

До реализации H1 закреплён [split 48 development / 12 holdout](../benchmarks/direct-evaluation-split-v1.json):
по два контрольных проекта на язык, минимум один с непустым графом. Это не слепая
выборка: артефакты R1/R2 уже исследовались. Ruby psych — единственный положительный
Ruby-проект, он попал в holdout; для настройки Ruby нужны независимые положительные
fixtures. Express остаётся development, его результат нельзя выдавать за holdout.

Следующий этап R4: прототип H1 отдельно от production, устанавливающий владельца
и прямую декларацию из кода, затем разрешающий версию по свидетельствам образа.
Проверять precision/recall/UNKNOWN и сохранность трёх SBOM на закреплённом split.
Эталон не передавать прототипу как вход.
